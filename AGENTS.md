# Strij

The ultimate goal for Strij is a distributed runtime for serverless functions. It must scale to thousands of nodes and to millions of concurrent tasks. Also it should avoid single points of failure in its design. This implies multiple gateway processes running in parallel. And every gateway process may run multiple worker threads where tasks are mapped to nodes in parallel. The design should allow experimenting with different pluggable scheduling policies.

C++23 gateway server and distributed node agent servers `io_uring`-based (Linux) event loop. Bazel 9.0.1 build.
Use `io_uring` as much as possible. Synchronous calls (e.g. `write(2)`) are acceptable when `io_uring` is not available (bootstrap and fallback paths) or too cumbersome to use. For example `posix_spawn` (fork+exec, directly on the event-loop thread), `pipe2`, `pidfd_open` (subscribed via `io_uring` poll), and the reaping `waitpid(WNOHANG)` after the pidfd poll fires are OK. See `src/nodeagent/extensions/task_handlers/piped_executable/child_process.cc`.

## Build system

- **Bazelisk** reads `.bazelversion` (9.0.1), Bzlmod with `MODULE.bazel`.
- Custom macros in `bazel/build_system.bzl`: `strij_cc_library`, `strij_cc_test`, `strij_cc_binary`, `strij_cc_test_library`.
- **Include prefix** is auto-derived: package `include/strij/event` → prefix `strij/event`, package `src/common/core/logging` → prefix `common/core/logging`. Includes use the prefix path, not the filesystem path.
- Test visibility is auto-added for `src/` packages → `test/` counterparts.
- `strij_cc_test` adds `@googletest//:gtest` automatically; **still need explicit `@googletest//:gtest_main`** for the test main.
- **Target naming convention:** libs → `_lib`, `_interface`, `_impl`, or descriptive suffix (e.g. `dispatcher_impl_lib`, `llhttp_parser_lib`, `command_interface`). Test targets: same as test file without `_test` suffix.
- **External deps:** `liburing` 2.14 via `configure_make`, `llhttp` 9.4.1 via `cmake`, `yaml_cpp` 0.7.0 via `http_archive` + inline BUILD. Bzlmod: `googletest` 1.17.0, `abseil-cpp` 20260107.1, `protobuf` 33.4, `rules_foreign_cc` 0.15.1.
- **Vendored third-party:** `rigtorp/SPSCQueue.h` (single-header, `cc_library` named `spsc_queue_lib`).
- **Root BUILD.bazel** builds `liburing` and `llhttp` via `rules_foreign_cc`.
- **Default toolchain:** host compiler (GCC). **Clang toolchain** at `//toolchain:cc_toolchain_for_linux_x86_64` enables ASan/TSan and libc++.

## Code conventions

- **Headers:** `.hh`, **sources:** `.cc`, **header guards:** `#pragma once`
- **Method names** are capitalized when public to distinguish them visually from private ones.
- **Private methods** are lowercase.
- **Constructors/destructors:** adhere to the C++ Rule of Five. Explicitly delete copy and move ctors if not needed to avoid unintended copies.
- **Struct/class members** use trailing underscore suffix (`success_`, `error_message_`) to distinguish them from scoped local variables.
- **Namespaces:** Use relative namespace prefixes, eg. `event::Dispatcher` to reference `strij::event::Dispatcher` when inside `strij::io` namespace. Namespace doctrine: shared concerns in bare namespaces (`strij::event`, `strij::io`, `strij::logging`, `strij::config`, `strij::task`, `strij::utils`); cross-cutting plugin scaffolding stays under `strij::extensions` (`Registry`, `Scheduler`, `FactoryContext`); side-owned types live in `strij::gateway` / `strij::nodeagent`, with bundled impls nested under a category sub-namespace (e.g. `strij::gateway::schedulers::RoundRobinSchedulerFactory`, `strij::nodeagent::task_handlers::EchoTaskHandler`). No literal `strij::common` namespace.
- **Format:** `.clang-format` — column 100, left-aligned pointers, grouped includes (std, system, "src", "exe", "test", rest).
- **Tag dispatch:** classes that implement `Completable` use `private enum Tags : uint8_t { kX = 0, kY = 1 }` for tag constants.
- **`using` aliases:** `DispatcherSharedPtr = std::shared_ptr<Dispatcher>`, `ChunkPtr = std::unique_ptr<Chunk>`, `ProtocolParserPtr = std::unique_ptr<ProtocolParser>`, `ResultReceiverPtr = std::unique_ptr<ResultReceiver>`, `SchedulerPtr = std::unique_ptr<Scheduler>`, `FunctionResolverPtr = std::unique_ptr<FunctionResolver>`, `ConnectionFactory = std::function<std::unique_ptr<ProtocolParser>(Connection&)>`.
- **Callbacks:** use `std::move_only_function<void(T)>` (C++23) for owning callbacks in parser/handler constructors.

## Architecture

- **Layout:** side-first tree mirroring the side split, with shared scaffolding in `common` and the curated public API under `include/`: sources `src/{common,gateway,nodeagent}/{core,extensions,exe}` (e.g. `src/common/core/{event,io,logging,config,utils,common}`, `src/common/extensions/scheduler_loader`, `src/gateway/core/{node_directory,result_receiver_storage,scheduler_router,...}`, `src/nodeagent/core/{admission_controller,run_task_service,task_handler_manager,function_resolver,...}`); **public extension contracts** (`Registry`, `FactoryContext` family, `Scheduler`) live in `include/strij/extensions/` with `//visibility:public` targets (`scheduler_interface`, `factory_context_lib`, `extension_registry_lib`); protos `api/common/{config,task,node}`, `api/gateway/...`, `api/nodeagent/...`; tests `test/{common,gateway,nodeagent}/...` mirroring `src/`; shared mocks `test/mocks/`.
- **Entrypoints:** `//src/gateway/exe:gateway` (`gateway.cc`) and `//src/nodeagent/exe:nodeagent` (`nodeagent.cc`)
- **Event loop:** `Dispatcher` (abstract) / `DispatcherImpl` (io_uring, 4096 entries). `Completable` handles completions via `HandleCompletion(tag, res, flags)`; `Command` struct carries `Type`/`destination_`/`args_`. `CommandHandler` receives commands via `ProcessCommand(Command)`.
- **Logging:** Singleton `Logger` runs its own `DispatcherImpl` in a dedicated thread. Each thread registers a `LogFrontend` (lock-free SPSC queue of 1024 `LogEntry`). `LogEntry` packs args into a 512-byte `args_data_` array with a `format_fn_` trampoline. Macros: `LOG_DEBUG()`, `LOG_INFO()`, `LOG_WARNING()`, `LOG_ERROR()`, `LOG_REGISTER_THREAD()`. Fallback: `write_stderr_fallback()` when no frontend registered. **String args** require custom `pack_arg` specializations (size-prefixed, in `log_frontend.hh`). Tests: `log_frontend_test.cc` validates pack/unpack round-trip.
- **I/O layer:** `Connection` (handles read/write via `Completable` tags `kRead`/`kWrite`), `TcpListener` (accepts multishot, owns `Connection` objects). `ProtocolParser` abstract interface with `GetReadBuffer()` → `OnData(size_t)` → `Action`. Implementations: `LlvhttpParser` (HTTP, wraps `llhttp`), `TlvParser` (TLV framing, 4096-byte buffer). `Chunk` (chunked buffer with body tracking).
- **Protocol:** `TlvFrame` struct (`type_id`, `value` span) with `SerializeTlvFrame()` helper. TLV types: `kTaskSubmission=0`, `kResult=1`, `kHeartbeat=2`, `kNodeAdvertisement=3`, `kNodeState=4`, `kTaskRejected=5`.
- **Gateway:** `GatewayHttpHandler` routes HTTP `/tasks/{type}` requests through the `SchedulerRouter`'s `Schedule` (fire-and-forget; receiver retained in `ResultReceiverStorage`, requirements resolved from headers/path). `GatewayTlvHandler` processes TLV result frames from node agents, delivers via `ResultReceiverStorage` (task_id → `ResultReceiver` storage); its default case is the frame-routing seam that hands unowned types to the scheduler (the `SchedulerRouter` claims `kTaskSubmission`). `HttpResultReceiver` writes TLV result back over HTTP connection. `Node` wraps a single node connection (states: `kInitial`→`kConnecting`→`kConnected`→`kDisconnected`). `NodeDirectory` manages node pool (`GetNextNode()`, `GetCandidates(protocol)` for capability-aware selection). `ParseTaskType()` extracts task type from path.
- **Upstream child routing (gateway):** the `SchedulerRouter` owns the `kTaskSubmission` claim. `HandleFrame` intercepts it and calls `handleChildSubmission`: parse `task::Task`, require the connection to own a `Node`, register a `NodeConnectionResultReceiver(task_id, conn.Mailbox())` in `ResultReceiverStorage` keyed by the **submitting** node's id, then dispatch through normal per-type `Schedule` routing with a forwarding receiver that erases the entry on terminal outcomes. `NodeConnectionResultReceiver` (TLV sibling of `HttpResultReceiver`) writes `kResult`/`kTaskRejected` frames over the submitting connection's mailbox; `TaskResult.is_final` is set explicitly (absence means final, proto3). Disconnect cleanup is free: `NotifyNodeDisconnected(submitting node id)` unwinds a node's outstanding forwarded children. `Size()`/`Empty()` and `Put`/`Get`/`Erase` via `ResultReceiverStorageImpl` (emplace semantics: first `Put` for a task id wins).
- **Node agent:** `NodeagentTlvHandler` is a thin seam: it owns **core** `kNodeAdvertisement` writes (`SendAdvertisement`) and routes every other inbound TLV frame into the node-side `NodeagentSchedulerRouter` (the frame demux: `router->HandleFrame(frame, conn)`, unknown types dropped with a warning, mirroring the gateway `SchedulerRouter`). The `default` local scheduler owns the child-outcome cases that resolve its `LocalReceiverRegistry` (unknown ids dropped with a warning; final erases). `RunTask` (core-owned) runs the execution path shared by node schedulers: parse → `GetHandler(type)` → `Admit` → `kTaskRejected` on failure → `AdmissionScope` + `AdmissionTrackingSender` + `ConnectionResultSender` → `handler->HandleTask`. `PushLocalScheduler` (registered as `"push"`) handles `kTaskSubmission` by calling `RunTask`.
- **Child task submission (node):** construction-injected seam for workflow handlers to spawn children. `TaskHandlerFactory` gets a `ChildTaskSubmitter&` from `NodeagentFactoryContext`; **the `TaskHandler::HandleTask(const Task&, ResultSenderPtr)` interface is unchanged** — submission is per-node via the shared context, not per-call. `NodeagentSchedulerRouter` (node-side `Scheduler` composite) routes by declared `task_type` / `local_default` roles and doubles as the frame demux (`HandledFrameTypes()` dedup union; `findFrameOwner` → NotFound when unclaimed). **The bundled `default` scheduler (factory `"default"`, empty config, no `RequiredProtocol`) is the node's single local authority**: its `Schedule` registers the child's receiver in its own `LocalReceiverRegistry` (mirror of `ResultReceiverStorage`) keyed by child id, then runs locally on admitted capacity via a `RegistryResultSender`-backed `RunTask`, or forwards (or errors + erases) when admission fails or no handler claims the type; it also owns the node's `kResult`/`kTaskRejected` frame cases, resolving that same registry. `push`/`probe` `Schedule()` are **Unimplemented** (log a warning + `DeliverError` — never hang). `GatewayClient` (a `ChildForwarder`) is the node's only outbound capability: every accepted connection registers its mailbox (`RegisterConnection(mailbox)`), `Forward(Task)` writes an upstream `kTaskSubmission` frame round-robin over live connections, and returns non-Ok when none are live (the default scheduler converts that into `DeliverError` + registry erase — never hangs). Route order in `nodeagent_framework.cc`: `GatewayClient` installed as the `ChildForwarder` **before** schedulers are built; the router is built from the configured schedulers and passed to every `NodeagentTlvHandler`.
- **Schedulers:** unified `Scheduler` contract — `Schedule(const task::Task&, ResultReceiverPtr)` (pure), `RequiredProtocol()` (pure), `HandleFrame(const io::TlvFrame&, io::Connection&)` (default no-op), `HandledFrameTypes()` (default empty). Every task must resolve through its receiver (result or error). Gateway side: `SchedulerRouter` composes per-`task_type` scheduler bindings (empty `task_type` = default) from `GatewayConfig.schedulers` (`round_robin`, `capability_aware`), created via `GatewaySchedulerFactory`. Node side: the bundled `default` scheduler is the single local authority (its `Schedule` = admit-or-forward policy); `push`/`probe` are wire-protocol counterparts with Unimplemented `Schedule`; created via `NodeSchedulerFactory`; their `RequiredProtocol()` feeds `BuildNodeCapabilities` (empty protocols skipped) and gates gateway node selection.
- **Extensions:** `Registry<FactoryInterface>` singleton template. `REGISTER_FACTORY(FactoryClass, FactoryInterface)` macro for simple names; `REGISTER_FACTORY_FULLY_QUALIFIED(FactoryClass, FactoryInterface, RegistrarName)` for namespace-qualified names. Factory contexts are split by side: `FactoryContext` base provides `Dispatcher()`; `GatewayFactoryContext` adds `NodeDirectory()` and `ResultReceiverStorage()`; `NodeagentFactoryContext` adds `FunctionResolver()`, `AdmissionController()`, `RunTask()`, `ChildTaskSubmitter()`, and `ChildForwarder()`. Concrete impls (`GatewayFactoryContextImpl`, `NodeagentFactoryContextImpl`) live in `src/gateway/exe/` / `src/nodeagent/exe/` and are compiled inline in the binaries (set `include_prefix`-less paths). Extension categories: `NodeDiscovery` / `NodeDiscoveryFactory` (node discovery plugins; `StaticNodeDiscovery` uses a hardcoded address list) in `src/gateway/extensions/node_discovery/`; task handlers (`ResultSender`, `TaskHandler` / `TaskHandlerFactory`, `EchoTaskHandler` in `src/nodeagent/extensions/task_handlers/echo`; loaded from `NodeAgentConfig.task_handlers` via `BuildTaskHandlerManager`); and schedulers (`GatewaySchedulerFactory` / `NodeSchedulerFactory`, implementations under `src/gateway/extensions/schedulers/{round_robin,capability_aware}` and `src/nodeagent/extensions/schedulers/{default,push,probe}`, composite routing in `src/gateway/core/scheduler_router/` and `src/nodeagent/core/nodeagent_scheduler_router`).
- **Scheduler contract** (`include/strij/extensions/scheduler.hh`, public) is shared across sides; `FunctionResolver` lives in `src/nodeagent/core/`. Loader helpers (`CreateGatewayScheduler`/`CreateNodeScheduler`, the config proto bridge) live in `src/common/extensions/scheduler_loader.hh`.
- **Config:** Template-based `LoadConfig<T>(path, cli_overrides)` → `absl::StatusOr<T>`. Uses protobuf config types (`GatewayConfig`, `NodeAgentConfig`) with YAML loading via `yaml_cpp`. Override precedence: defaults → YAML → env vars (`STRIJ_{APP}_{FIELD_PATH}`) → CLI overrides (`field.subfield=value`). Array env: `STRIJ_GATEWAY_NODE_CONNECTIONS__0__ADDRESS`. CLI flags via `absl::Flags`.
- **Signal handling:** `SignalMonitor` uses `signalfd` + `Completable` interface for graceful shutdown.
- **Utils:** `GenerateTaskId()` returns a random hex string.
- **Protobuf:** `api/common/task/task.proto` (`Task`/`TaskResult`, `TaskResult.is_final` optional; absence means final — consumers treat `!has_is_final() || is_final()` as final, since proto3 forbids explicit defaults), side-split config schemas `api/gateway/config/gateway.proto` and `api/nodeagent/config/nodeagent.proto` with shared `api/common/config/{extensions,options}.proto`; node capabilities `api/common/node/capabilities.proto`; extension configs beside their side packages: `api/nodeagent/extensions/task_handlers/{echo,piped_executable}/*.proto`, `api/gateway/extensions/node_discovery/static/static_node_discovery.proto`, `api/gateway/extensions/schedulers/{round_robin,capability_aware}/*.proto`, `api/nodeagent/extensions/schedulers/push/push_scheduler.proto`.
