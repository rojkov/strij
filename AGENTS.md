# Strij

The ultimate goal for Strij is a distributed runtime for serverless functions. It must scale to thousands of nodes and to millions of concurrent tasks. Also it should avoid single points of failure in its design. This implies multiple gateway processes running in parallel. And every gateway process may run multiple worker threads where tasks are mapped to nodes in parallel. The design should allow experimenting with different pluggable scheduling policies.

C++23 gateway server and distributed node agent servers `io_uring`-based (Linux) event loop. Bazel 9.0.1 build.
Use `io_uring` as much as possible. Synchronous calls (e.g. `write(2)`) are acceptable only on bootstrap/fallback paths or where `io_uring` is too cumbersome: `posix_spawn` (fork+exec on the event-loop thread), `pipe2`, `pidfd_open` (subscribed via `io_uring` poll), and reaping `waitpid(WNOHANG)` after the pidfd poll fires — see `src/nodeagent/extensions/task_handlers/piped_executable/child_process.cc`.

## Build system

- **Bazelisk** reads `.bazelversion` (9.0.1), Bzlmod with `MODULE.bazel`.
- Custom macros in `bazel/build_system.bzl`: `strij_cc_library`, `strij_cc_test`, `strij_cc_binary`, `strij_cc_test_library`.
- **Include prefix** is auto-derived: package `include/strij/event` → prefix `strij/event`, package `src/common/core/logging` → prefix `common/core/logging`. Includes use the prefix path, not the filesystem path.
- Test visibility is auto-added for `src/` packages → `test/` counterparts.
- `strij_cc_test` adds `@googletest//:gtest` automatically; **still need explicit `@googletest//:gtest_main`** for the test main.
- **Target naming convention:** libs → `_lib`, `_interface`, `_impl`, or descriptive suffix (e.g. `dispatcher_impl_lib`, `llhttp_parser_lib`, `command_interface`). Test targets: same as test file without `_test` suffix.
- **External deps:** `liburing` 2.14 via `configure_make`, `llhttp` 9.4.1 via `cmake`, `yaml_cpp` 0.7.0 via `http_archive` + inline BUILD. Bzlmod: `googletest` 1.17.0, `abseil-cpp` 20260107.1, `protobuf` 33.4, `rules_foreign_cc` 0.15.1.
- **Vendored third-party:** `rigtorp/SPSCQueue.h` (single-header, `cc_library` named `spsc_queue_lib`).
- **Root BUILD.bazel** builds `liburing` and `llhttp` via `rules_foreign_cc`.
- **Default toolchain:** host compiler (GCC). **Clang toolchain** at `//toolchain:cc_toolchain_for_linux_x86_64` enables ASan/TSan and libc++.

## Code conventions

- **Headers:** `.hh`, **sources:** `.cc`, **header guards:** `#pragma once`
- **Method names** are capitalized when public to distinguish them visually from private ones.
- **Private methods** are lowercase.
- **Constructors/destructors:** adhere to the C++ Rule of Five. Explicitly delete copy and move ctors if not needed to avoid unintended copies.
- **Struct/class members** use trailing underscore suffix (`success_`, `error_message_`) to distinguish them from scoped local variables.
- **Namespaces:** Use relative namespace prefixes, eg. `event::Dispatcher` to reference `strij::event::Dispatcher` when inside `strij::io` namespace. Namespace doctrine: shared concerns in bare namespaces (`strij::event`, `strij::io`, `strij::logging`, `strij::config`, `strij::task`, `strij::utils`); cross-cutting plugin scaffolding stays under `strij::extensions` (`Registry`, `Scheduler`, `FactoryContext`); side-owned types live in `strij::gateway` / `strij::nodeagent`, with bundled impls nested under a category sub-namespace (e.g. `strij::gateway::schedulers::RoundRobinSchedulerFactory`, `strij::nodeagent::task_handlers::EchoTaskHandler`). No literal `strij::common` namespace.
- **Format:** `.clang-format` — column 100, left-aligned pointers, grouped includes (std, system, "src", "exe", "test", rest).
- **Tag dispatch:** classes that implement `Completable` use `private enum Tags : uint8_t { kX = 0, kY = 1 }` for tag constants.
- **`using` aliases:** `DispatcherSharedPtr = std::shared_ptr<Dispatcher>`, `ChunkPtr = std::unique_ptr<Chunk>`, `ProtocolParserPtr = std::unique_ptr<ProtocolParser>`, `ResultReceiverPtr = std::unique_ptr<ResultReceiver>`, `SchedulerPtr = std::unique_ptr<Scheduler>`, `FunctionResolverPtr = std::unique_ptr<FunctionResolver>`, `ConnectionFactory = std::function<std::unique_ptr<ProtocolParser>(Connection&)>`.
- **Callbacks:** use `std::move_only_function<void(T)>` (C++23) for owning callbacks in parser/handler constructors.

## Architecture

Behavioral requirements live in OpenSpec specs: settled specs in `openspec/specs/`, the active child-task work in `openspec/changes/child-tasks-and-local-execution/`. **When this file and a spec disagree on behavior, the spec wins** — this file keeps repo/navigation facts and gotchas, while specs describe behavior (and can lag on paths). Key specs by area: event `command-handler`/`dispatcher-connect`; I/O `connection-completable`/`protocol-parser`; wire `typed-tlv-messages`/`task-protocol`/`node-advertisement`; gateway `gateway-task-bridge`/`node-directory`/`dynamic-node-directory`/`node-discovery`; nodeagent `node-local-scheduler`/`nodeagent-task-handlers`; child tasks `child-task-submission`/`child-result-routing`/`gateway-client`; scheduling `pluggable-scheduler`; extensions `extension-registry`/`extension-api-surface`; config `yaml-config-loader`/`gateway-config`/`nodeagent-config`; utils `readable-task-id-generation`; logging `stderr-fallback-logging`.

- **Layout:** side-first tree mirroring the side split, with shared scaffolding in `common` and the curated public API under `include/`: sources `src/{common,gateway,nodeagent}/{core,extensions,exe}` (e.g. `src/common/core/{event,io,logging,config,utils,common}`, `src/common/extensions/scheduler_loader`, `src/gateway/core/{node_directory,result_receiver_storage,scheduler_router,...}`, `src/nodeagent/core/{admission_controller,run_task_service,task_handler_manager,function_resolver,...}`); **public extension contracts** (`Registry`, `FactoryContext` family, `Scheduler`) in `include/strij/extensions/` with `//visibility:public` targets (`scheduler_interface`, `factory_context_interface`, `extension_registry_lib`); protos `api/{common,gateway,nodeagent}/...`; tests `test/{common,gateway,nodeagent}/...` mirroring `src/`; shared mocks `test/mocks/`. Spec: `extension-api-surface`.
- **Entrypoints:** `//src/gateway/exe:gateway` (`gateway.cc`) and `//src/nodeagent/exe:nodeagent` (`nodeagent.cc`)
- **Event loop:** `Dispatcher` (abstract) / `DispatcherImpl` (io_uring, 4096 entries). `Completable` handles completions via `HandleCompletion(tag, res, flags)`; `Command` (`Type`/`destination_`/`args_`) is delivered to `CommandHandler::ProcessCommand`. Specs: `command-handler`, `dispatcher-connect`.
- **Logging:** Singleton `Logger` runs its own `DispatcherImpl` in a dedicated thread; each thread registers a lock-free SPSC `LogFrontend` (1024 `LogEntry`, args packed into a 512-byte `args_data_` with a `format_fn_` trampoline). Macros: `LOG_DEBUG()`, `LOG_INFO()`, `LOG_WARNING()`, `LOG_ERROR()`, `LOG_REGISTER_THREAD()`. Fallback `write_stderr_fallback()` when no frontend registered. Gotcha: **string args require custom `pack_arg` specializations** (size-prefixed, in `log_frontend.hh`). Spec: `stderr-fallback-logging`.
- **I/O layer:** `Connection` (tags `kRead`/`kWrite`), `TcpListener` (multishot accept, owns `Connection`s). `ProtocolParser`: `GetReadBuffer()` → `OnData(size_t)` → `Action`. Implementations: `LlvhttpParser` (HTTP, wraps `llhttp`), `TlvParser` (TLV, 4096-byte buffer). `Chunk` (chunked buffer with body tracking). Specs: `connection-completable`, `protocol-parser`.
- **Protocol:** `TlvFrame` (`type_id`, `value` span) + `SerializeTlvFrame()`. Frame types and wire format: spec `typed-tlv-messages` (type_id 0–10, incl. probe constants). Task/result payloads: spec `task-protocol`.
- **Gateway:** `GatewayHttpHandler` routes HTTP `/tasks/{type}` through the `SchedulerRouter`'s `Schedule` (fire-and-forget; receiver retained in `ResultReceiverStorage`). `GatewayTlvHandler` demuxes inbound TLV frames; its default case is the frame-routing seam that hands unowned types to the scheduler (the router claims `kTaskSubmission`). `HttpResultReceiver` writes TLV results back over HTTP. `Node` wraps a node connection (`kInitial`→`kConnecting`→`kConnected`→`kDisconnected`). `NodeDirectory`: `GetNextNode()`, `GetCandidates(protocol)`. `ParseTaskType()` extracts type from path. Specs: `gateway-task-bridge`, `node-directory`.
- **Upstream child routing (gateway):** the `SchedulerRouter` owns the `kTaskSubmission` claim. `HandleFrame` → `handleChildSubmission`: parse `task::Task`, require the connection to own a `Node`, register a `NodeConnectionResultReceiver(task_id, conn.Mailbox())` in `ResultReceiverStorage` keyed by the **submitting** node's id, then dispatch through normal per-type `Schedule` routing with a forwarding receiver that erases the entry on terminal outcomes. `NodeConnectionResultReceiver` writes `kResult`/`kTaskRejected` frames (TLV sibling of `HttpResultReceiver`). Gotchas: `TaskResult.is_final` is set explicitly (absence means final, proto3); `NotifyNodeDisconnected(node)` unwinds a node's outstanding forwarded children; `ResultReceiverStorageImpl` `Put` is emplace — first `Put` for a task id wins. Spec: `child-result-routing` (active change).
- **Node agent:** `NodeagentTlvHandler` is a thin seam: owns core `kNodeAdvertisement` writes (`SendAdvertisement`), routes every other inbound frame into the node-side `NodeagentSchedulerRouter` frame demux (unknown types dropped with a warning, mirroring the gateway `SchedulerRouter`). Core-owned shared execution path `RunTask`: parse → `GetHandler(type)` → `Admit` → `kTaskRejected` on failure → `AdmissionScope` + `AdmissionTrackingSender` + `ConnectionResultSender` → `handler->HandleTask`. Specs: `node-local-scheduler`, `node-advertisement`.
- **Child task submission (node):** construction-injected seam: `TaskHandlerFactory` gets a `ChildTaskSubmitter&` through `TaskHandlerDeps`; **`TaskHandler::HandleTask(const Task&, ResultSenderPtr)` is unchanged**. The bundled `default` local scheduler (factory `"default"`, empty config, no `RequiredProtocol`) is the node's single local authority: its `Schedule` registers the child's receiver in its own `LocalResultReceiverStorage` by child id (then runs locally via a `StorageResultSender`-backed `RunTask`, or forwards — or errors + erases — when admission fails or no handler claims the type); it owns the node's `kResult`/`kTaskRejected` frame cases. `push`/`probe` `Schedule()` are **Unimplemented** (log a warning + `DeliverError` — never hang). `GatewayClient` (a `ChildTaskForwarder`) is the node's only outbound path: accepted connections register their mailbox (`RegisterConnection`), `Forward(Task)` writes an upstream `kTaskSubmission` frame round-robin over live connections, and returns non-Ok when none are live (→ `DeliverError` + storage erase). Wiring (`nodeagent_framework.cc`): build the `TaskHandlerManager` empty → `RunTaskServiceImpl` over it → fetchers/`DataDependencyFetcherRouter` → schedulers/`NodeagentSchedulerRouter` → then populate the manager via `LoadTaskHandlers`; the router is passed to every `NodeagentTlvHandler`. Specs: `child-task-submission`, `child-result-routing`, `gateway-client` (active change).
- **Schedulers:** unified `Scheduler` contract (`include/strij/extensions/scheduler.hh`, public) — `Schedule(const task::Task&, ResultReceiverPtr)` (pure), `RequiredProtocol()` (pure), `HandleFrame(const io::TlvFrame&, io::Connection&)` (default no-op), `HandledFrameTypes()` (default empty). Every task must resolve through its receiver (result or error). Gateway side: `SchedulerRouter` composes per-`task_type` bindings (empty `task_type` = default) from `GatewayConfig.schedulers` (`round_robin`, `capability_aware`) via `GatewaySchedulerFactory`. Node side: local schedulers via `NodeSchedulerFactory` (`default`, `push`, `probe`); their `RequiredProtocol()` feeds `BuildNodeCapabilities` (empty protocols skipped) and gates gateway node selection. Loader helpers (`CreateGatewayScheduler`/`CreateNodeScheduler`, the config proto bridge) in `src/common/extensions/scheduler_loader.hh`. Specs: `pluggable-scheduler`, `node-local-scheduler`.
- **Extensions:** `Registry<FactoryInterface>` singleton template. `REGISTER_FACTORY(FactoryClass, FactoryInterface)` for simple names; `REGISTER_FACTORY_FULLY_QUALIFIED(FactoryClass, FactoryInterface, RegistrarName)` for namespace-qualified names. Gateway factory contexts: `FactoryContext` base provides `Dispatcher()`/`SharedDispatcher()`; `GatewayFactoryContext` adds `NodeDirectory()` and `ResultReceiverStorage()` (concrete impl `GatewayFactoryContextImpl` in `src/gateway/exe/`). Nodeagent factories instead receive per-category reference bundles: `TaskHandlerDeps` (`strij/nodeagent/task_handlers.hh`), `NodeSchedulerDeps` (`strij/extensions/scheduler.hh`), `DataDependencyFetcherDeps` (`strij/extensions/data_dependency_fetcher.hh`). Specs: `extension-registry`, `extension-api-surface`.
- **Config:** `LoadConfig<T>(path, cli_overrides)` → `absl::StatusOr<T>`; override precedence defaults → YAML → env vars (`STRIJ_{APP}_{FIELD_PATH}`, arrays e.g. `STRIJ_GATEWAY_NODE_CONNECTIONS__0__ADDRESS`) → CLI overrides (`field.subfield=value`, `absl::Flags`). Specs: `yaml-config-loader`, `gateway-config`, `nodeagent-config`.
- **Signal handling:** `SignalMonitor` uses `signalfd` + `Completable` for graceful shutdown. (No spec.)
- **Utils:** `GenerateTaskId()` returns a random hex string. Spec: `readable-task-id-generation`.
- **Protobuf:** schemas under `api/` — side-split configs `api/gateway/config/gateway.proto` and `api/nodeagent/config/nodeagent.proto` (shared `api/common/config/{extensions,options}.proto`), node capabilities `api/common/node/capabilities.proto`, tasks `api/common/task/{task,probe}.proto`, extension configs beside their side packages (task handlers, node discovery, schedulers). Gotcha: `TaskResult.is_final` absence means final (proto3) — consumers use `!has_is_final() || is_final()`. Specs: `task-protocol`, config specs above.
